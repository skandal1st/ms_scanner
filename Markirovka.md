# Коды маркировки (МойСклад JSON API Remap 1.2)

Выдержка из официальной документации МойСклад по сущности **Коды маркировки** (`trackingCodes` в составе позиций документов). Актуальная версия: [dev.moysklad.ru](https://dev.moysklad.ru/doc/api/remap/1.2/).

Средствами JSON API можно получать, создавать, редактировать и удалять коды маркировки. Ключевое слово сущности — `trackingCodes`. Сущность включает идентификатор, текстовый код, тип кода и массив вложенных КМ. Коды относятся к отдельной позиции конкретного документа. Порядок вывода КМ первого уровня фиксирован; вложенные КМ могут выводиться в случайном порядке.

## Атрибуты сущности

| Название       | Тип            | Описание                                      | Свойство в запросе     | Обязательно в ответе | Expand |
|----------------|----------------|-----------------------------------------------|-------------------------|----------------------|--------|
| id             | UUID           | ID кода маркировки                            | только чтение           | да                   | нет    |
| cis            | String         | Код маркировки в **стандартном формате**      | обязательно при создании| нет                  | нет    |
| cis_1162       | String         | Код маркировки в формате тега 1162            | только чтение           | нет                  | нет    |
| type           | String         | Тип кода маркировки                           | обязательно при создании| да                   | нет    |
| trackingCodes  | Array(Object)  | Вложенные коды маркировки                     | —                       | нет                  | нет    |

Пример эндпоинта в документации МС:  
`/entity/{entityType}/{entityId}/positions/{positionId}/trackingCodes`

## Получить коды маркировки позиции документа

### Параметры запроса

| Параметр | Описание |
|----------|----------|
| **limit**  | number (optional), по умолчанию **100**, допустимо 1–100. Максимум сущностей в выборке. |
| **offset** | number (optional), по умолчанию **0**. Смещение в списке. |
| **codetype** | number (optional), по умолчанию **`gs1`**. Формат возвращаемых КМ. |

### Значения `codetype`

| Значение   | Описание |
|------------|----------|
| `gs1`      | Стандартный формат |
| `tag_1162` | В формате тега 1162 |
| `all`      | Все доступные форматы |

### Ответ 200

В успешном ответе: `meta`, `context`, массив `rows` — объекты кодов маркировки с перечисленными полями.

## Массовое создание и обновление кодов маркировки

В теле запроса — массив JSON-представлений КМ для создания или обновления. Обновляемые КМ должны содержать **идентификатор**.

Результат — массив созданных и обновлённых сущностей. **Вложенные КМ заменяются** указанными в запросе.

### Пример: POST на позицию документа

Создание КМ отдельным запросом (рекомендуемый путь в приложении для документов, у которых позиции уже есть в МС):

```http
POST /entity/supply/{supplyId}/positions/{positionId}/trackingCodes
Content-Type: application/json
```

```json
[
  {
    "id": "f591e101-1bc0-11ec-ac18-000c00000004",
    "cis": "012345678912345576",
    "type": "transportpack"
  },
  {
    "cis": "010463003759026521LjJfNII5aXL-B",
    "type": "trackingcode"
  }
]
```

Ответ `200` — массив созданных/обновлённых КМ (для новых записей МС присваивает `id`).

Типы в примере: `transportpack` (транспортная упаковка), `trackingcode` (единичный КМ). Наш поток отгрузки/приёмки с сканом Data Matrix использует **`type`: `trackingcode`**.

---

## Массовое удаление кодов маркировки

В теле — массив метаданных удаляемых КМ или список с идентификаторами. Если у КМ есть вложенные коды, они тоже удаляются.

---

## Связь с этим репозиторием

- **Позиции уже есть в МС**: см. выше; `cis` строится из `trackingType` в карточке товара: **24** символа (`21`+6 серии) для `SOFT_DRINKS`, `WATER`, `MILK`, `FOOD_SUPPLEMENT`, `SANITIZER`; **25** (`21`+7) для `TOBACCO`, `OTP`, `NCP`; иначе — полная нормализованная строка (остальные типы — по мере проверки на 17102). Сырой скан вида «14 цифр GTIN + хвост» без `01`/`21` перед отправкой в МС приводится к элементной строке GS1.
- **Позиций ещё нет** (редкий путь): те же КМ передаются в `PUT` внутри `positions[].trackingCodes`, как раньше.
- Поле **`cis_1162`** при создании через наш поток не задаётся (в документации МС — только для чтения в ответе).
