# Статусы при начале сборки

В настройках юрлица независимо выбираются статус отгрузки и статус заказа покупателя. По умолчанию оба выключены. Статусы применяются при открытии выбранной отгрузки для сборки: на ПК через POST /documents/{id}/start-collection, на ТСД через выбор отгрузки. Просмотр прогресса в iframe и обновление данных статусы не меняют. Передача марок больше не меняет статусы.

Миграция 20261005_05 добавляет shipment_start_state_id и customer_order_start_state_id. Прежние поля *_sent_state_id сохраняются для истории и совместимости отката, но больше не используются. Прежние значения не переносятся: статус завершения обычно не подходит для начала сборки. Новые статусы нужно выбрать в настройках.

Общий обработчик сериализует открытие по пользователю и идентификатору отгрузки МС, включая несколько ТСД и старые дубликаты локальных документов. В Document.upd_meta.collection_start сохраняются выбранные статусы и завершённые шаги. Переоткрытие не возвращает статус назад. При частичной ошибке повторное открытие продолжает незавершённый шаг. Для отгрузки без заказа меняется только её статус. Связь заказа проверяется напрямую или через общий счёт; неоднозначная связь блокирует смену статусов.

Статус меняется отдельным PUT только поля state, без передачи позиций и марок. При ошибке сборка не открывается, пользователь видит сообщение и может повторить открытие.

Для изменения customerOrder решению требуется update в дескрипторе. Обновлённый moysklad-descriptor.xml нужно загрузить в dev.moysklad.ru и переустановить решение для получения нового Vendor-токена.

Изменения остаются локально по просьбе пользователя. Прод не обновлялся.
