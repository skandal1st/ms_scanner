# Защита сборки при удалении отгрузки в МойСкладе

Номер отгрузки не является её идентификатором. После удаления и пересоздания
документ с прежним номером получает новый ID. Скандата не должна автоматически
переносить в него марки: план, склад и юрлицо могут измениться.

При открытии на ПК и ТСД проверяется поле `deleted` исходной отгрузки.
Удалённый документ нельзя открыть для сборки. Перед отправкой проверка
повторяется в API и непосредственно перед записью в МС из воркера.
При сбое чтения отправка не продолжается вслепую.

При открытии отгрузки из заказа проверяются другие незавершённые сборки
этого заказа и юрлица, содержащие сканы. Если их отгрузка удалена в МС,
пользователь получает сообщение о сохранённых марках и необходимости переноса.
Другие действующие отгрузки одного заказа разрешены. В пути обычного скана
новых обращений к МС нет.

Для восстановления сначала сохраняется резервная копия обеих сборок, сканов,
действий и сессий ТСД. В транзакции блокируются документы и проверяются их
владелец, юрлицо, заказ, статусы и актуальная связь с МС. Проверяются склад,
план и отсутствие конфликтующих сканов в целевой сборке. Переносятся сканы
с исходными ID и записи действий ТСД; старые активные сессии завершаются.
В `upd_meta.scan_transfer` обеих записей сохраняется история переноса.

Исходный документ получает `upd_meta.superseded_by_document_id`: редактирование
и отправка этой сборки блокируются, а её карточка сохраняется для истории.
ТСД должен открыть действующую отгрузку заново. Перенос не отправляет марки
в МойСклад и не отмечает документ собранным.
