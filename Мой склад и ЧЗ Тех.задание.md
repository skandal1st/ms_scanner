**Проект:** Интеграция приемки маркированных товаров  
**Интеграции:** МойСклад + Честный Знак

---

# 1. 🎯 Цель системы

Разработать веб-приложение, позволяющее:

- принимать маркированные товары **в одном интерфейсе**
- исключить переключение между системами
- автоматизировать проверку и ввод в оборот

---

# 2. 👥 Пользователи

- Кладовщик (основной)
- Администратор (настройки интеграций)

---

# 3. 🧱 Архитектура

### Общая схема:

```
Frontend (Web)   ↓Backend API   ↓-------------------------| МойСклад API         || Честный Знак API     |-------------------------   ↓Database + Queue
```

---

# 4. ⚙️ Функциональные требования

## 4.1 Авторизация

### Требования:

- Регистрация пользователя
- Авторизация (JWT)
- Хранение подключений:
    - API ключ МойСклад
    - токен Честный Знак

---

## 4.2 Экран "Приемка товаров" (ключевая часть)

### UI блоки:

#### 1. Выбор документа

- список поступлений из МойСклад
- либо создание нового

---

#### 2. Сканирование кодов

Поддержка:

- USB-сканер (как ввод с клавиатуры)
- ручной ввод

Поведение:

- каждый скан → добавление в список
- мгновенная проверка

---

#### 3. Таблица кодов

Колонки:

- Код маркировки
- Статус проверки
- Товар
- Ошибка

Статусы:

- ✅ валиден
- ❌ ошибка
- ⚠️ дубликат
- ⏳ проверяется

---

#### 4. Проверка кодов (Честный Знак)

Для каждого кода:

- проверка существования
- проверка статуса (в обороте / нет)
- принадлежность

---

#### 4.5 Автосопоставление товаров

Логика:

- код → GTIN → товар
- поиск в МойСклад

Если не найден:

- подсветка
- возможность ручного выбора

---

#### 4.6 Работа с УПД

Функции:

- загрузка входящих УПД из ЧЗ
- отображение состава
- сверка с фактом

---

#### 4.7 Подтверждение приемки

Кнопка: **"Принять товары"**

Действия:

1. отправка данных в Честный Знак
2. создание/обновление документа в МойСклад
3. логирование результата

# 🧱 Главный экран: Приемка товаров

## 📐 Общий принцип

- **1 экран = 1 задача**
- максимум действий с клавиатуры/сканера
- никаких модалок “на подумать”

---

# 🖥️ Структура экрана

```
---------------------------------------------------------| Верхняя панель                                        || [Документ ▼] [УПД ▼]        Статус: ● В процессе       |---------------------------------------------------------| ЛЕВАЯ ЗОНА (40%)        | ПРАВАЯ ЗОНА (60%)            ||-------------------------|------------------------------|| Сканирование            | Таблица кодов                ||                         |                              || [ Поле ввода ]          | Код | Товар | Статус | ⚠     ||                         |------------------------------|| Последний скан:         | XXXX | Nike | ✅ |            || 010290...               | XXXX | ?    | ❌ | ошибка     ||                         | XXXX | Puma | ⚠ | дубль      ||                         |                              || Статистика:             |                              || ✔ Валид: 120            |                              || ❌ Ошибки: 5            |                              || ⚠ Дубли: 3             |                              |---------------------------------------------------------| Нижняя панель                                        || [ Очистить ]   [ Проверить ]   [ ✅ Принять товары ]   |---------------------------------------------------------
```

---

# 🔥 Как это работает (реальный сценарий)

## 1. Кладовщик открывает экран

- уже выбран документ из МойСклад
- или подтянут УПД из Честный Знак

---

## 2. Начинает сканировать

**Важно:**

- курсор всегда в поле ввода
- сканер = клавиатура → Enter → следующий

👉 Никаких кликов мышкой

---

## 3. Что происходит при каждом скане

Мгновенно:

- код добавляется в таблицу
- уходит в backend
- возвращается статус

### В таблице:

- ✅ зеленый → ок
- ❌ красный → проблема
- ⚠ желтый → дубль

---

## 4. UX детали (которые решают всё)

### 🟢 Автофокус

Поле ввода **никогда не теряет фокус**  
(иначе кладовщик тебя проклянет)

---

### 🔊 Звук

- ✅ короткий “пик”
- ❌ противный “бззз”

Да, это важно. Они не смотрят на экран постоянно.

---

### ⚡ Без задержек

Если проверка долгая:

- сразу статус ⏳
- потом обновление

---

### 🚫 Ошибки — не блокируют поток

Плохая система:

> “Ошибка! Остановитесь!”

Нормальная:

- ошибка просто в таблице
- работа продолжается

---

## 5. Работа с ошибками

Клик по строке:

```
--------------------------------Код: 010290...Ошибка: не найден в ЧЗ[ Выбрать товар вручную ▼ ][ Удалить ]--------------------------------
```

---

## 6. Автосопоставление

Если GTIN найден:

- товар подставляется сам

Если нет:

- строка подсвечена
- можно быстро выбрать

---

## 7. Кнопка "Принять товары"

Перед нажатием:

```
✔ Валид: 120❌ Ошибки: 5⚠ Дубли: 3[ Принять только валидные ][ Отмена ]
```

Модалка = удобно “показать форму”, но ты делаешь **потоковую операцию на сотни сканов**. Там модалки начинают ломать UX.

---

# 🚫 Почему модалка — ловушка

### 1. Потеря фокуса

Сканер = клавиатура.  
Любой клик мимо → фокус улетел → кладовщик орёт.

---

### 2. Ограниченное пространство

Тебе нужно:

- список кодов
- статусы
- ошибки
- статистика

В модалке это превращается в:

> “а давайте добавим скролл внутри скролла” — худшее из UX.

---

### 3. Закрыл окно = потерял контекст

- случайно нажал ESC
- браузер лагнул  
    → до свидания, 300 отсканированных кодов

---

### 4. Производительность

МойСклад не рассчитан на heavy real-time UI внутри себя  
особенно если ты через iframe/виджет пихаешь

## ⚙️ Как это выглядит логически

### Кнопка:

```
📦 Приемка маркировки
```

### JS логика (упрощенно):

```
const docId = CURRENT_DOCUMENT_ID;const userToken = MOYSKLAD_TOKEN;const redirectUrl = `https://your-app.ru/auth?doc=${docId}&token=${userToken}`;window.open(redirectUrl, '_blank');
```

**НЕ передавай токен как есть** (иначе потом будешь лечить безопасность)

# 🔐 Как сделать безопасно

## Шаги:

### 1. Кнопка дергает твой backend:

```
POST /generate-session{  moysklad_token,  doc_id}
```

---

### 2. Backend:

- проверяет токен
- создаёт временную сессию (например 1 минута)
- возвращает ссылку:

```
https://your-app.ru/s/abc123
```

---

### 3. Пользователь переходит по ссылке

→ уже авторизован  
→ документ загружен

---

# 🧠 Почему так

Если передашь токен напрямую:

- его можно перехватить
- утечка = доступ ко всему складу


# ⚙️ Пошаговая схема

## Шаг 1: Получение challenge

Запрос:

```
GET /api/v3/auth/cert/key
```

Ответ:

```
{  "uuid": "abc-123",  "data": "base64_string"}
```

---

## Шаг 2: Подпись challenge

Ты берёшь:

- `data`
- подписываешь через УКЭП

👉 тут чаще всего используют:

- CryptoPro CSP
- или node bindings (через плагины/обертки)

---

## Шаг 3: Отправка подписи

```
POST /api/v3/auth/cert/
```

```
{  "uuid": "abc-123",  "data": "signed_data_base64"}
```

---

## Шаг 4: Получение токена

Ответ:

```
{  "token": "access_token",  "expire": 3600}
```

---

## Шаг 5: Использование

Дальше в каждом запросе:

```
Authorization: Bearer access_token
```

# 🧠 Важный момент (где все падают)

## ❗ Подпись — это не просто “захешировать”

Это:

- ГОСТ алгоритмы
- сертификаты
- контейнеры ключей

👉 обычный Node.js **не умеет это из коробки**

---

# ⚙️ Как это реально реализуют

## Вариант 1: Через CryptoPro (классика)

- ставишь CryptoPro CSP
- используешь:
    - COM объект (Windows)
    - или CAdES plugin

👉 минусы:

- боль
- зависит от ОС
- танцы с драйверами

---

## Вариант 2: Через локальный агент (рекомендую)

Ты делаешь:

### 1. Маленькое приложение на ПК клиента

(“агент”)

Он:

- имеет доступ к сертификату
- подписывает данные

---

### 2. Твое веб-приложение

```
Frontend → Agent (localhost) → подпись → Backend → ЧЗ
```

---

👉 это самый стабильный вариант

---

## Вариант 3: Через облачную подпись

- КриптоПро DSS
- облачные сертификаты

👉 тогда можно без локального ПО
