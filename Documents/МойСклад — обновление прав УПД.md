# Обновление прав МойСклад для автозаполнения УПД

В `moysklad-descriptor.xml` добавлены только права чтения:

```xml
<company><view/></company>
<factureOut><view/></factureOut>
```

`company` — контрагенты (JSON API `/entity/counterparty`),
`factureOut` — выданные счета-фактуры (`/entity/factureout`).
Права записи этих сущностей и административный scope не требуются.
Описание прав: https://dev.moysklad.ru/doc/api/vendor/1.0/#informaciya-o-prawah-dostupa

## Действия владельца решения

1. Открыть решение Скандата в кабинете разработчика https://dev.moysklad.ru/.
2. Загрузить обновлённый `moysklad-descriptor.xml` из корня репозитория и применить
   изменения к используемой версии решения. Если кабинет требует выпуска новой
   версии, завершить этот процесс до переустановки рабочего экземпляра.
3. В нужном аккаунте МойСклад удалить установленное решение и установить его заново
   из обновлённой версии. Выполнять вне активной сборки: старый токен при удалении
   перестаёт работать. Обновление страницы и повторный вход сами по себе не меняют права.
4. Открыть Скандату из МойСклад. При активации МойСклад передаст новый токен серверу;
   Скандата зашифрует и сохранит его автоматически. Копировать или присылать токен не нужно.
5. Открыть завершённую отгрузку → «XML УПД» и проверить реквизиты покупателя,
   номер и дату связанного счёта-фактуры. Для СЧФДОП номер/дата берутся из счёта-фактуры
   и защищены от случайного изменения.

Переустановка на том же аккаунте сохраняет пользователя Скандаты, сборки и настройки
ЧЗ/СБИС: деактивация очищает только токен МойСклад и состояние его подписки,
а активация обновляет существующую интеграцию по accountId.

## Условия автозаполнения

- У покупателя в МойСклад должны быть заполнены ИНН, КПП для ЮЛ, юридический адрес,
  фамилия и имя для ИП. Пустые реквизиты не восстанавливаются из названия карточки.
- Счёт-фактура должен быть связан с конкретной отгрузкой через `factureOut`.
  При отсутствии связи Скандата не ищет похожий документ по номеру и не создаёт его.
- Права выше не дают идентификаторы ящиков ЭДО и полномочия подписанта. Они не являются
  реквизитами покупателя или счёта-фактуры из API МойСклад.
- Уже загруженный в СБИС УПД остаётся сохранённым снимком XML: смена токена не
  перезаписывает его и не создаёт новую редакцию.

До переустановки старый токен продолжит возвращать ограничения доступа. Реальную
проверку новых прав можно завершить только после выдачи обновлённого токена.
